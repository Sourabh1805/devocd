# T64b — Do the tests notice a broken rule? (mutation spot-check)

**Branch:** `test/mutants` · **Size:** S · **Rules:** [README](README.md)
**Starts after T64 (#75) is merged** (it reuses its folder and edits the next ledger line).

## Goal
Coverage says a line ran; it does not say a test would fail if the line were wrong. For the four
modules whose rules matter most, break one rule at a time and prove the suite fails. Where it
does not, add the missing test. Keep the mutants as a table so the check can be rerun.

## Facts
- Modules and their tests:
  - `scripts/lib/claims.mjs` (`validateClaims`, `currentness`, `normalizeStatement`,
    `statementGroups`, `independentSupport`): `tests/unit/claims.test.mjs`
  - `scripts/lib/redundancy.mjs` (`findRepeats`, `memoryDirFor`): `tests/unit/redundancy.test.mjs`
  - `scripts/lib/refresh.mjs` (`clearStale`, `refreshStatus`, `planRefresh`,
    `sourceFingerprint`, `baselineRefresh`, `completeRefresh`): `tests/unit/refresh.test.mjs`,
    `refresh-impact.test.mjs`

    `traceKnowledge`, `reviewContext`): `tests/unit/trace.test.mjs`
- Coverage of `scripts/lib` is gated by `npm run coverage` (T64).

## Owns
- `tests/tools/mutants.mjs` (new)
- New tests only, added to `tests/unit/claims.test.mjs`, `redundancy.test.mjs`,

- `package.json` (`scripts` only: add `mutants`)

**No change to any file under `scripts/`, apart from the temporary mutation the tool makes and
restores.** Do not edit or weaken any existing test.

## Steps
1. **`tests/tools/mutants.mjs`**: a table `MUTANTS = [{ id, file, find, replace, rule, tests }]`.
   `find` is an exact string that must occur **exactly once** in `file` (refuse to run
   otherwise). For each mutant: replace, run `node --test` on its `tests` only, restore the
   original bytes, record `killed` (the run failed) or `survived` (it passed).
   - Refuse to start when any target file has uncommitted changes (`git status --porcelain`).
   - Restore in `finally`, and also on SIGINT. After the run, check every target file is
     byte-identical to its original; if not, write it back and exit 2.
   - Print one line per mutant (`killed` / `survived`, id, rule) and exit 1 if any survived.
   - Positional ids run only those mutants.
2. **Twelve mutants, three per module.** Each changes what a rule decides, not how it is
   written. For each module pick:
   - a **boundary**: `<` ↔ `<=`, an off-by-one in a count or a date comparison;
   - a **negation or dropped guard**: remove a `!`, return early, or delete one condition of
     an `&&` / `||`;
   - a **wrong result**: return the other status, drop an item from a list, swap two fields.
   The `rule` column says, in plain words, what goes wrong for a user if the mutant shipped
   (for example "a stale page is reported as fresh"). A mutant that makes the code throw on
   every call or fail to parse does not count; pick another.
3. Run all twelve. For every **survivor**, add one test (a table row where a table exists)
   that kills it. Show it: the new test fails with the mutant in place and passes without.
   If a survivor is behaviour that does not matter (an equivalent mutant), say why in the PR
   and keep it in the table with `equivalent: true`, which the tool reports but does not
   count as a failure. At most two may be equivalent.
4. `npm run mutants` runs the whole table. It is **not** added to CI.

## Done when
- `npm run mutants` exits 0: every mutant killed or marked equivalent.
- `npm test`, `node scripts/validate-plugin.mjs` and `npm run coverage` pass;
  `git status scripts/` is clean.
- The PR has the table of twelve: id, module, rule, killed on the first run or killed by a new
  test (name it), or equivalent (why), and the time `npm run mutants` takes.
- Show the safety: interrupt a run with Ctrl+C partway (or kill the child), then show
  `git status scripts/` is clean.
- T64b ticked in `docs/TASKS.md` with the PR link.
