## Goal
`/devocd:install` asks once whether company policy is kept in a git repo, and records this
person's clone in company state. After this task, a company can be set up with a policy repo
end to end without editing `state.json` by hand. Reading policy from the repo is still T110 and
T111.

## Facts
- T108 added `policyRepo { path, remote, index, builtAt }` to company state:
  - `policyRepoProblem` validates it, and `stateProblem` calls it;
  - `policyRepoStatus` gives the clone's read-only status;
  - `preflight` reports `company.policyRepo`.
  All of that is in `scripts/lib/policyrepo.mjs`.
- Install never writes `state.json` itself. The skill writes `.devocd/state.draft.json`, and
  `render-parent . <draft>` applies it through `applyDraft` in `scripts/lib/parent.mjs`.
  `readDraft` validates the draft with `stateProblem`, so a bad `policyRepo` is already refused.
  `applyDraft` keeps `decisionCapture` when the draft leaves it out (look for "Omission
  preserves preferences"). `policyRepo` needs the same treatment.
- The interview is one AskUserQuestion round
  ([skills/install/references/interview.md](../../skills/install/references/interview.md)).
  Non-interactive runs take an answers file instead (same page, "Answers file").
- The skill's `allowed-tools` must list exactly the helper commands the skill names. A contract
  test in `tests/unit/plugin-contract.test.mjs` checks this.
- **The model must never type the remote URL.** It comes from the clone's own `origin`, read by
  the helper. DevOCD never runs `git clone`, `fetch` or `pull` (design: approach A).

## What to build
1. **`node scripts/devocd.mjs policy-repo-probe <clone> [--index <path>] --json`** (read-only).
   It prints the exact `policyRepo` object for the draft:
   `{ path, remote, index, builtAt: null }`.
   - `path` is the clone root in absolute form with forward slashes.
   - `remote` is the clone's `origin`, read with `git -C <clone> remote get-url origin`.
   - `index` defaults to `index.md`.
   - The output also includes `status` (from `policyRepoStatus`) and `indexExists`. Both are
     for the skill to report; they are not state fields.
   - **Refused, exit 1:** the folder is not a clone root, there is no `origin`, or the
     resulting field fails `policyRepoProblem`. One example is an origin with credentials in
     it: the refusal says so **without repeating the URL**. Bad arguments exit 2, as for other
     commands.
   - The logic goes in `scripts/lib/policyrepo.mjs` (`probePolicyRepo(clone, { index })`). The
     CLI only parses the arguments.
2. **`applyDraft`:**
   - a draft that leaves out `policyRepo` keeps the existing one;
   - a draft with `"policyRepo": null` removes it, by deleting the key before validation;
   - a draft with an object sets it, and the object is validated as today.
3. **Install skill:**
   - Add the `policy-repo-probe` grant to `allowed-tools`.
   - Add a **fourth question** to the interview round: "Is company policy kept in a git repo?"
     - **"No — keep policies here"** (recommended). No `policyRepo` field; behaviour is as
       today.
     - **"Yes — I have a clone"**: one follow-up asks for the clone path. Run the probe. On
       success, put the printed `policyRepo` (without `status` or `indexExists`) into the draft,
       and list it in the draft shown for approval. If `indexExists` is false, say that the repo
       has no index yet, so no policy will be routed until there is one.
     - **"Yes, but I have no clone yet"**: one follow-up asks for the URL. Show the
       `git clone <url>` line for the person to run, and record nothing. Tell them to rerun
       install after cloning. Never run that command yourself.
   - On a rerun, a company that already has `policyRepo` shows it and its status (from
     `preflight`) as the recommended answer. "Stop using the repo" puts `"policyRepo": null`
     in the draft.
   - Answers file: an optional `"policyRepo": { "path": "...", "index": "..." }`. The path is
     relative to the answers file's folder, like a file `ref`. The probe still runs, and a
     refusal stops the run before anything is written.
4. **Template:** add one short paragraph to `parent-template.md` on the `policyRepo` draft field
   (the probe output only, never hand-written).
5. **CLI help:** the `settings` usage line says it takes "the company standards folder" only.
   Since T108 it also takes the policy repo clone. Fix that line, and add the
   `policy-repo-probe` usage line.

## Tests (AGENTS.md › Tests)
- **`probePolicyRepo`**, as a table on real temp clones (`gitRepo` in
  `tests/helpers/workspace.mjs`):
  - ok, with the remote taken from `origin`;
  - a custom `--index`;
  - `indexExists` true and false;
  - a subfolder of a clone is refused;
  - no `origin` is refused;
  - an origin with credentials is refused, and the message does not contain the secret;
  - an invalid index is refused.
- **One CLI test for `policy-repo-probe`:** exit 0 with JSON, exit 1 on a refusal, exit 2 on
  bad arguments.
- **`applyDraft`**, as a table: omitted keeps, `null` removes, an object sets, and an invalid
  object leaves state and parent byte-identical.
- **Safeguard rows** (rules, not prose):
  - install never runs `git clone`, `fetch` or `pull`;
  - the remote comes from the probe, never typed;
  - "no clone yet" records nothing;
  - the probe runs before the draft.
- Show that each new test fails without its code: break it, run, restore.
