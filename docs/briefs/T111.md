# T111 — The graph, trace and refresh point at files in the policy repo

## Goal
When a company records a policy repo, a page's `Standards: <topic>` line resolves to a file in
the person's clone of that repo. The graph and `trace` name that file and the commit it was read
at, and `refresh-status` notices when a governing file in the repo changes, the same way T120
notices a changed local standards page. Nothing writes to the repo.

## Facts
- `policyRepo { path, remote, index, builtAt }` lives in company `.devocd/state.json`
  (`scripts/lib/policyrepo.mjs`, T108). `policyRepoProblem(value)` validates it;
  `policyRepoStatus(value)` runs the read-only git probes and returns
  `{ path, remote, index, head, builtAt, status }`, status one of
  `ok | missing | not-a-clone | wrong-remote | moved | no-git`. `policyRepo: null` means "no repo"
  (T109).
- A project finds its company through `state.companyRel` (see `standardsDir` in
  `scripts/lib/refresh.mjs`, T120). A company is its own governing folder.
- `buildKnowledge(dir)` in `scripts/lib/knowledge.mjs` (line ~150) turns each page's topics into
  `governed-by` edges to `standards/<topic>.md`: an edge when that page is in the graph (the
  company graph), an `external` item otherwise (a project graph). Topics must match
  `TOPIC = /^[a-z0-9]+(-[a-z0-9]+)*$/`. The graph is `{ version: 3, nodes, edges, external,
  sources, skipped, scopes, projects }`.
- `trace` (`scripts/lib/trace.mjs`, line ~233) collects `governed-by` targets of the pages on the
  chain into `policies`: `{ id, title, estimatedTokens }` for a node, `{ external }` otherwise.
- `refresh.mjs` (T120, T121): `snapshot` records `standards: { 'security.md': sha256 }`;
  `changedStandards` maps changed files to topics (skipping `index.md`); `dependentPages` lists
  the module and flow pages whose `Standards:` line names a changed topic; `refreshStatus`
  reports `reason: 'standards-changed'`, `standardsChanged`, `stalePages`.
- The prompt hook parses `standards/index.md` lines with
  `/^\s*[-*]\s+(.+?):\s*\[[^\]]*\]\(([^)\s]+)\)/` and a `safeTarget` rule
  (`scripts/devocd-hooks.mjs`, lines 52 and 167), with a 64 KiB cap. T110 will switch the hook to
  the reader this task adds, so match that line format exactly.
- `tests/helpers/workspace.mjs` has `gitRepo(dir, { origin })` for clone-shaped fixtures.

## Decided by the controller
1. **Topic = the linked file's name without `.md`.** `[PR description](pr/description.md)` is
   topic `description`. A name that does not match `TOPIC` gives no topic (the entry still routes
   for the hook). Two index entries whose files share a name make that topic **ambiguous**: it
   resolves to neither, and the reader reports it.
2. **Policy files are not graph nodes.** The graph gains a top-level
   `policies: [{ id: 'policy:<repo path>', path: '<repo path>', sha256, commit }]` (empty without
   a repo), and `governed-by` targets `policy:<repo path>` as an `external` item. Policy text is
   never copied into the graph, search or viewer.
3. **`builtAt` is recorded per project, not in company state.** Refresh runs per project, and
   two projects can be built at different commits, so one company field would be wrong for one
   of them. The project's refresh snapshot records `policy: { commit, files }`; company
   `state.json` is **not** written by this task. T112 compares the clone's HEAD with each
   project's recorded commit. (This narrows the design's "refresh records `builtAt`"; the
   company field stays as T108 defined it.)
4. **Repo mode** applies when the governing company state has a valid, non-null `policyRepo`
   whose status is `ok` or `moved` and whose index file reads. Otherwise everything behaves as
   today, from local `standards/`. Local standards and a repo at the same time: the repo wins
   (the warning about both is T114's).

## What to build
**1. `readPolicyIndex(policyRepo)` in `scripts/lib/policyrepo.mjs`** — file reads only, no git,
no network, so the hook can use it in T110. Returns
`{ entries: [{ trigger, file, topic }], topics: Map<topic, file>, problems: [{ line, reason }] }`
or `null` when the index cannot be read. Rules:
- The index is `<path>/<index>`: a regular file, not a symlink, at most 64 KiB, UTF-8.
- Lines use the hook's format above. A target loses any `#fragment`; a URL, a scheme, an absolute
  path or a backslash is refused. It resolves relative to the index's folder; after normalising,
  it must not leave the clone, and after `realpath` it must still be inside the clone's
  `realpath`. It must be a regular `.md` file that is not a symlink. Every refusal is a
  `problems` row (no path text beyond the repo-relative target, and never a secret: run
  `scanSecrets` on the target and drop it if it matches).
- A missing target is a `problems` row with reason `missing-target`, not an entry.
- `topics` holds only unambiguous topics; an ambiguous one is a `problems` row.

**2. Graph (`knowledge.mjs`)** — in repo mode, a topic in `topics` gives an `external`
`governed-by` item to `policy:<file>`; a topic the index does not resolve gives an `external`
item to `policy-topic:<topic>`. `policies` lists each resolved file once, with its sha256 (null
when the file is over the per-file cap `MAX_FILE`) and `commit` = the status's `head`. Without
repo mode the graph is exactly as today plus `policies: []`. Decide whether `version` changes:
bump it only if a reader checks it, and say which in the PR.

**3. Trace (`trace.mjs`)** — a `policy:` target becomes
`{ id, path: '<clone path>/<repo path>' (forward slashes), commit }` in `policies`.

**4. Refresh (`refresh.mjs`)** — the snapshot adds `policy: { commit, files: { '<repo path>':
sha256 } } | null`, hashing only files the index links to (not the index itself). `refreshStatus`
compares files exactly as T120 compares `standards`, maps a changed file to its topic through the
current index, and reports it through the same fields (`reason: 'standards-changed'`,
`standardsChanged`, `stalePages`). A commit that changed no linked file is **not** a reason to
refresh. An old baseline without `policy` records no change.

## Tests (AGENTS.md › Tests)
- One table for `readPolicyIndex` over a real `gitRepo` fixture: a valid entry; `..` inside the
  clone (allowed); `..` leaving the clone; an absolute link; a URL; a symlinked target; a missing
  target; a non-`.md` target; two files with the same name (ambiguous); an index over 64 KiB; a
  symlinked index.
- Graph: a project page with `Standards: description` in repo mode gets the `policy:` external
  item and the `policies` row with sha256 and commit; the same workspace without `policyRepo` is
  unchanged except `policies: []`; status `missing` falls back to local standards.
- Trace: the chain's policy reports the clone path and commit.
- Refresh: after a baseline, editing a linked repo file reports `standards-changed` with the topic
  and the stale page; a new commit that only touches an unlinked file reports `current`.
- Show each new test fails without its code: break it, run, restore.
- Never write to the fixture repo after its first commit except through the test's own edits; the
  code under test must not run any git command other than T108's probes.
