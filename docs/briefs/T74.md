# T74 — The prompt hook gives each policy pointer once per session

**Branch:** work on `feat/prompt-once`, created from `brief/T74` (which carries this brief).
**Size:** S · **Rules:** [README](README.md) · **Starts after T77 (#80) is merged.**

## Goal
The prompt hook makes no model calls; its only cost is the text it adds to the conversation.
Today it adds the same policy pointer every time a prompt mentions the topic, so a session about
Jira tickets pays for the Jira pointer on every message. Give each pointer once per session, never
add anything to a slash command, and make the cost visible with a read-only `hook-stats` command.

## Facts
- `onPrompt` in `scripts/devocd-hooks.mjs` reads the company's `.devocd/standards/index.md`,
  matches its `- Trigger words: [title](target.md)` lines against the prompt's words, and returns
  up to 3 pointers in one `additionalContext` string: `DevOCD policy for this request: <a>; <b>`.
  Each pointer is `<trigger text> → read <path>`, where `<path>` is relative to `cwd`.
- Since T77 the hook input carries `session_id` (captured by `scripts/lib/hookinput.mjs`).
  It comes from Claude Code and goes into a file name here, so it must be validated.
- The hooks write only inside the session scope's own `.devocd/` folder, never through a link;
  `onEdit` and `recordUntracked` show the checks (`lstatOrNull`, not a link, a real folder).
  `.devocd/journal/` is exempt from restore and is the place for hook bookkeeping.
- `onSessionStart` prints at most one line today (stale pages, untracked edits). Keep that.
- Hook latency is tested (`performance: each handler averages under 50 ms`, median of 21).
- **T78 (controller, later)** changes how `stale.json` and `edits.jsonl` are stored. Do not touch
  `onEdit`, `recordUntracked`, `clearStale` or those files.

## Steps
1. **Slash commands:** a prompt whose first non-space character is `/` gets no pointer.
2. **Once per session:** when `session_id` matches `^[A-Za-z0-9_-]{1,128}$`, remember the
   pointers given in `.devocd/journal/session-<session_id>.json` of the session's scope
   (`findScope(input.cwd)`), as `{ "given": ["<standards target>", …], "t": "<ISO time>" }`.
   - A pointer is identified by its standards target (the link target), not its text.
   - A pointer already in `given` is left out. If every match was given before, return `null`.
   - Up to 200 entries per file; past that, stop recording (pointers may repeat, which is safe).
   - Read and write with the journal checks `onEdit` uses; any error means "remember nothing"
     and the hook behaves as today. A missing or invalid `session_id` also behaves as today.
3. **Cleanup:** `onSessionStart` removes `session-*.json` files in that journal folder whose
   `mtime` is older than 7 days, looking at no more than 500 entries, skipping links and
   anything that is not a regular file. Errors are swallowed. It never changes its message.
4. **Counters:** every `onPrompt` and `onSessionStart` call updates
   `.devocd/journal/hook-stats.json` in its scope: `{ "since": <ISO>, "events": { "<event>":
   { "runs": n, "injected": n, "bytes": n } } }`, where `bytes` is the UTF-8 length of the
   `additionalContext` returned (0 when nothing). Read, add, write, same checks; errors swallowed.
   Concurrent sessions may lose an increment: the counts are approximate, and say so.
5. **`devocd hook-stats <dir>`**: read-only. Prints one line per event
   (`<event>: <runs> runs, <injected> injected, <bytes> bytes (~<bytes/4> estimated tokens)`)
   and the `since` date; `--json` prints the object. No counters file: say so, exit 0. A
   malformed file: one error line, exit 1. Never writes. Usage errors exit 2.
6. **Header comment** of `devocd-hooks.mjs`: list what the hooks write (journal, stale marks,
   session memory, counters), all inside `.devocd/`.
7. **README** Settings paragraph: hooks make no model or network calls; what they add is at most
   three policy pointers per prompt (each once per session) and one line at session start;
   `devocd hook-stats <dir>` shows the counts; `devocdHooks: false` turns them off.

## Tests
- `hooks.test.mjs`, through `onPrompt` directly (in process):
  - the same matching prompt twice in one session: pointers the first time, `null` the second;
  - a second prompt matching one old and one new topic gives only the new pointer;
  - a new `session_id` gives the pointer again;
  - no `session_id`, and `session_id` values `../x`, `a/b`, `x` × 129, `""`: pointers every
    time, and no file is written outside `.devocd/journal/` (list the folder);
  - `/devocd:refresh jira ticket` gets nothing;
  - a `session-<id>.json` that is a link, or a journal folder that is a link: nothing written
    through it, pointers still given;
  - the counters after two prompts and one session start have the right runs, injected and
    bytes (bytes equal `Buffer.byteLength` of the returned text);
  - session start removes a `session-*.json` with an `mtime` 8 days old and keeps one 6 days old.
- `hookstats.test.mjs`: the text and `--json` output for a counters file, no file (exit 0), a
  malformed file (exit 1), a missing argument (exit 2); and the command writes nothing.
- The latency test still passes; paste the medians before and after.
