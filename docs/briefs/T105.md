# T105 — The hook timing test stops failing at random

**Branch:** `test/hook-timing` · **Size:** S · **Rules:** [README](README.md)
**Starts after T64b (#77) is merged.**

## Goal
`performance: each handler averages under 50 ms` in `tests/unit/hooks.test.mjs` fails now and
then on a busy machine, and it cannot run under coverage at all, so `tests/tools/coverage.mjs`
skips it by its exact name. Make it measure the handlers, not the machine's worst moment, and
let the test itself decide when timing means nothing.

## Facts
- The test (`tests/unit/hooks.test.mjs`, around line 256) runs each handler (`onPrompt`,
  `onEdit`, `onSessionStart`) once to warm up, then 20 times, and asserts the **mean** is under
  50 ms. One garbage collection or a scheduler stall in those 20 runs moves the mean.
- `tests/tools/coverage.mjs` passes `--test-skip-pattern=performance: each handler averages
  under 50 ms`. Renaming the test silently ends the skip, and the gate turns flaky.
- `NODE_V8_COVERAGE` is set in every process the coverage tool runs.
- The hooks run once per prompt, edit or session start, in their own process. The 50 ms budget
  is for the handler's work; Node start-up is not part of it and is not measured here.

## Owns
- `tests/unit/hooks.test.mjs` (that one test only)
- `tests/tools/coverage.mjs` (remove the name-matched skip)
- `docs/TASKS.md` (T105 line only)

No change under `scripts/` or `hooks/`. The 50 ms budget does not change.

## Steps
1. Measure with the **median** of 21 timed runs per handler (after the warm-up), and assert the
   median is under 50 ms. Print the median and the slowest run per handler on the `#` line, as
   now, so a slow handler is still visible.
2. The test skips itself with `t.skip('timing is meaningless under coverage')` when
   `process.env.NODE_V8_COVERAGE` is set. Remove `SKIP_WALL_CLOCK` and its
   `--test-skip-pattern` argument from `tests/tools/coverage.mjs`.
3. Keep the test name unchanged.
