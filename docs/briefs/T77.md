# T77 — Large edits are still tracked

**Branch:** work on `feat/large-edits`, created from `brief/T77` (which carries this brief).
**Size:** M · **Rules:** [README](README.md) · **Starts after T105 (#79) is merged.**

## Goal
The edit hook marks knowledge pages stale when their source files change. Today it gives up on
any hook input over 256 KiB, and a `Write` of a large file carries the whole file in its input,
so exactly the big edits go untracked, silently. Read the input as a stream, keep only the few
fields the hooks use, never be fooled by text inside the file content, and when the edited path
cannot be established, leave a notice instead of staying silent.

## Facts
- `scripts/devocd-hooks.mjs`, main block (bottom of the file): reads stdin into one string,
  `process.exit(0)` past 256 KiB, then `JSON.parse` and `dispatch(input)`.
- What the handlers read from the input, and nothing else:
  - every event: `hook_event_name`, `cwd`
  - `UserPromptSubmit` (`onPrompt`): `prompt`
  - `PostToolUse` (`onEdit`): `tool_name`, and `tool_input.file_path` or
    `tool_input.notebook_path`
  - `session_id` is not read yet; T74 will need it, so capture it too.
- A hook input is one JSON object. For `Write`, `tool_input.content` is the whole file; for
  `Edit`/`MultiEdit`, `old_string`/`new_string`/`edits` can be large. `tool_response` can repeat
  the content. Key order is not guaranteed: `file_path` may come after `content`.
- `onEdit` returns early unless the event is `PostToolUse` with a tool in `EDIT_TOOLS` and an
  absolute path. It writes `.devocd/journal/edits.jsonl` and `.devocd/stale.json` in the edited
  file's own scope (`findScope(dirname(file))`).
- `onSessionStart` prints one line when `stale.json` lists pages.
- `clearStale(root, t0)` in `scripts/lib/refresh.mjs` clears marks after a refresh; marks from
  edits journaled after `t0` are kept.
- **T78 (controller, next)** will replace `stale.json` with one file per mark. Do not change how
  `stale.json` or `edits.jsonl` are written.

## Steps
1. **`readHookInput(stream, { maxBytes = 64 * 1024 * 1024 })`** in `scripts/lib/hookinput.mjs`,
   async, returns `{ input, complete }`:
   - A small state machine over the bytes as they arrive (decode UTF-8 with a streaming
     decoder; never hold the whole input). It tracks nesting (`{`, `[`), whether it is inside a
     string, escapes (`\"`, `\\`, `\uXXXX`, including surrogate pairs), and the current key path.
   - It **captures** only these paths, as strings: `hook_event_name`, `session_id`, `cwd`,
     `tool_name`, `prompt`, `tool_input.file_path`, `tool_input.notebook_path`. Each captured
     value is capped (prompt 256 KiB, the rest 4 KiB); a value over its cap is truncated and
     `prompt` keeps its first 256 KiB, any other capped value is dropped.
   - Keys are compared **after** unescaping (`"file_path"` is `file_path`). A repeated key
     takes the last value, as `JSON.parse` does. A captured path whose value is not a string is
     ignored.
   - Every other value, however long, is skipped character by character and never stored.
   - `complete` is true only when one whole top-level object was read and only whitespace
     follows. Invalid JSON, a truncated stream, a top level that is not an object, or input past
     `maxBytes` gives `complete: false` with whatever was captured so far.
   - `input` has the shape the handlers expect: top-level fields, and `tool_input` as an object
     holding only `file_path` / `notebook_path` when seen.
2. **Main block:** use `readHookInput(process.stdin)`. If `complete`, `dispatch(input)` as now.
   If not complete: when `hook_event_name` is `PostToolUse` and `tool_name` is in `EDIT_TOOLS`
   (as far as they were captured), call `recordUntracked(input.cwd)`; otherwise do nothing.
   The handlers themselves do not change.
3. **Also untracked:** a complete `PostToolUse` edit input whose path is missing, not a string or
   not absolute. Today `onEdit` returns `null` there; have `dispatch` (not `onEdit`) call
   `recordUntracked(input.cwd)` in that case.
4. **`recordUntracked(cwd)`**: finds the scope of `cwd`; if hooks are enabled there, writes
   `.devocd/journal/untracked.json` as `{ "since": <first ISO time>, "last": <latest ISO time>,
   "count": <n> }` (read, update, write; never through a link; the same safety checks `onEdit`
   uses for the journal folder). Optional bookkeeping: any error is swallowed.
5. **`onSessionStart`**: when `untracked.json` exists with `count > 0`, add one line:
   `DevOCD: <n> edit(s) could not be tracked; run /devocd:refresh to check what changed.`
   It joins the stale line if both apply (one `additionalContext`, two sentences). Strip it to
   printable ASCII like the stale line.
6. **`clearStale(root, t0)`**: remove `untracked.json` when there is no `t0` or its `last` is
   not after `t0`; keep it when an untracked edit happened after the snapshot began.

## Tests
- `hookinput.test.mjs` (table-driven), each through a `Readable` that delivers the input in
  small chunks (for example 7 bytes), so state across chunk boundaries is exercised:
  - the captured fields of a small `Write`, `Edit`, `NotebookEdit`, `UserPromptSubmit` and
    `SessionStart` input equal what `JSON.parse` gives for the same fields;
  - `file_path` after a 5 MiB `content`;
  - content holding `"file_path": "/evil"`, `\"file_path\":\"/evil\"`, a nested
    `{"tool_input":{"file_path":"/evil"}}`, and `tool_response.filePath` never change the
    captured path; neither does a `file_path` key nested deeper (`tool_input.edits[0].file_path`);
  - `"file_path"` as the key, a surrogate pair in the value, and a repeated key;
  - truncated input, invalid JSON, an array at the top level, trailing garbage, and input past
    a small `maxBytes` → `complete: false`;
  - a prompt over 256 KiB is truncated to 256 KiB.
  - **Agreement check:** for a set of at least 20 generated inputs (random key order, random
    escapes in content, random nesting), the captured fields equal `JSON.parse`'s.
- `hooks.test.mjs` (new tests, real child processes like the existing stdin test):
  - a 5 MiB `Write` of a mapped source marks its page stale and journals the edit, with
    `file_path` before and after the content; the hook process finishes in under 2 s;
  - truncated stdin for an edit writes `untracked.json`, and the next session start says so;
  - a complete edit input with no `file_path` writes `untracked.json`;
  - a truncated `UserPromptSubmit` writes nothing.
- `refresh.test.mjs`: `clearStale` removes the notice for an untracked edit before `t0` and keeps
  it for one after.
