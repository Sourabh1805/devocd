# T63 — Make the four slowest test files fast without losing coverage

**Branch:** `test/fast-suite` · **Size:** M · **Rules:** [README](README.md)

## Goal
Cut unit-suite time by testing behaviour through the library instead of starting the CLI as a
new process for every case, while every behaviour stays covered.

## Facts (measured on `main`, 2026-11-23: 723 tests, ~59 s)
Slowest tests, all starting `node scripts/devocd.mjs …` per case:
| File | Test | Time |
|---|---|---|
| `capture.test.mjs` | invalid state and broken registration cannot enable or fall through | 21.4 s |
| `capture.test.mjs` | registered scope tri-state matrix through CLI | 19.8 s |
| `parent-draft.test.mjs` | install reruns preserve omitted preferences… | 15.2 s |
| `settings.test.mjs` | CLI settings refuses any other folder, value or state… | 15.2 s |
| `reviewdiff.test.mjs` | exit codes: 0 ok, 1 refusal, 2 usage… | 11.7 s |
| `capture.test.mjs` | explicit project preferences do not depend on company configuration | 10.7 s |
| `settings.test.mjs` | CLI settings: the standards folder preflight gives… | 9.8 s |

## Owns
`tests/unit/capture.test.mjs`, `settings.test.mjs`, `parent-draft.test.mjs`,
`reviewdiff.test.mjs`. **No production code changes.** If a behaviour can only be reached
through the CLI, keep that case on the CLI.

## Steps
1. Record before: total duration and each file's duration
   (`node --test --test-reporter=spec tests/unit/<file>`), and line coverage of `scripts/lib`
   with `node --test --experimental-test-coverage "tests/unit/**/*.test.mjs"`.
2. For each matrix above, call the library function the CLI wraps with the same inputs and
   assert the same outcomes (return values, thrown error codes, files on disk).
3. Keep exactly one CLI test per command touched that proves the wiring: argument parsing and
   the exit-code mapping (0 ok, 1 refusal, 2 usage, 3 environment).
4. Same assertions, same or more test names: never drop a case from a matrix.
5. Record after: the same three measurements.

## Done when
- Each of the seven tests above runs under 3 s, or the PR explains why one cannot.
- Total suite time drops at least 30%.
- `scripts/lib` line coverage is unchanged or higher.
- Test count is unchanged or higher.
- Before/after numbers are in the PR, with every interpretation listed.
