# T61 — Turn near-identical tests into tables

**Branch:** `test/table-tests` · **Size:** S · **Rules:** [README](README.md)
**Starts after T63 is merged** (both edit `parent-draft` and `settings` tests).

## Goal
Where several tests repeat the same body with different inputs, keep one body and a table of
cases, so a fix to the shared setup happens once.

## Facts
- `parent-draft.test.mjs` has a family of refusals that differ only in the draft:
  "a draft with key rules too long / not JSON / the wrong kind / a missing field / a bad
  source / a bad parent file name / a parent that cannot fit", each asserting "state and
  parent stay byte-identical, the draft goes, exit 1".
- `split.test.mjs` has a family "refuses a non-blank line in no list / overlapping ranges /
  a range outside the file / a range backwards / an inline line outside the file / a bad
  name / a repeated name / a team file that escapes the folder / an absolute team file /
  a multi-line topic", each asserting "writes nothing and still deletes the plan".
- `protect.test.mjs` and `settings.test.mjs` have similar refusal families.

## Owns
`tests/unit/parent-draft.test.mjs`, `split.test.mjs`, `protect.test.mjs`, `settings.test.mjs`.
No production code changes.

## Steps
1. For each family, write `const CASES = [{ name, input, … }]` and
   `for (const c of CASES) test(\`<family prefix>: ${c.name}\`, () => { … })`.
2. **Keep every test name the same** so the count and the names in the report are unchanged.
3. Keep every assertion; a case that needs an extra assertion keeps it via a field in its row.
4. Leave tests that are not part of a family alone.

## Done when
- Test count and the list of test names are identical before and after (paste both counts and
  a `diff` of the sorted names, which must be empty).
- Lines in the four files go down; put before/after line counts in the PR.
- Every interpretation listed in the PR.
