## Goal
A company can record a **policy repo**: a git repo owned by one person, of which each teammate
has their own clone. This task adds only the configuration and the read-only status of that
clone. Nothing reads policies from the repo yet: that work is T110 and T111.

## Facts
- Company state is `.devocd/state.json`, validated by `stateProblem(s)` in `scripts/lib/check.mjs`
  (line ~67). Optional fields such as `completion` and `devocdHooks` are allowed to be absent, so
  older installs stay valid. `policyRepo` follows the same pattern.
- A company's `.devocd/` is personal: DevOCD keeps it out of git (`assertNotTracked`,
  `.git/info/exclude`). So `policyRepo.path` is this person's own clone path, and every field
  lives in `state.json`. There is no second file.
- `preflight(dir)` in `scripts/lib/preflight.mjs` returns `company: { path, rel, project,
  standards } | null` from `findCompany`, which today never reads the state contents.
- `runGit(dir, args)` in `scripts/lib/protect.mjs` runs git with argv only (no shell) and returns
  `{ ok, out, status }`. `insideWorkTree` throws `GIT_MISSING` when git cannot be run. Use these;
  never use a shell or `exec`.
- `assertSettingAllowed` in `scripts/devocd.mjs` lets `settings add-dir|remove-dir` take only
  the company standards folder (`samePath` comparison).
- The hooks do not call `preflight`. This task must not touch `scripts/devocd-hooks.mjs`.

## The field
```json
"policyRepo": {
  "path": "D:/work/company-policy",
  "remote": "https://github.com/acme/policy",
  "index": "index.md",
  "builtAt": null
}
```
`stateProblem` returns a message (the state then fails `check` as today) when `policyRepo` is
present and any of these fails:
- It is an object with exactly these four keys.
- `path` is an absolute path with forward slashes, at most 1024 characters.
- `remote` is a non-empty string of at most 512 characters, either `https://host/…` or
  `git@host:…`, carrying **no password**. An `https://user:secret@host/…` URL is refused, and the
  message never repeats the URL.
- `index` is a relative path ending in `.md` with no `..`, `.` or empty segment, no leading `/`
  and no backslash, at most 256 characters.
- `builtAt` is null or a 40-character or 64-character lowercase hex commit id.

## The status (new `scripts/lib/policyrepo.mjs`)
- `export function normalizeRemote(url)`: lowercases the host and drops a trailing `.git` and
  trailing `/`. It makes `git@host:owner/repo` and `https://host/owner/repo` equal. It returns
  null for anything it cannot parse.
- `export function policyRepoStatus(policyRepo)` → `{ path, remote, index, head, builtAt, status }`.
  It is **read-only** and runs no git command that changes anything or uses the network. The
  first rule that applies decides `status`:

| status | when |
|---|---|
| `missing` | `path` does not exist, is not a directory, or is a symlink (`lstat`) |
| `no-git` | git cannot be run |
| `not-a-clone` | `git -C path rev-parse --show-toplevel` fails, or names a folder other than `path` (so a subfolder of a repo is refused) |
| `wrong-remote` | `remote get-url origin` fails, or its `normalizeRemote` differs from `remote`'s |
| `moved` | `builtAt` is set and `rev-parse HEAD` differs from it |
| `ok` | otherwise, including when `builtAt` is null |

  `head` is the HEAD commit id, or null when it is not known.
- `preflight`: when the company state has a valid `policyRepo`, `company.policyRepo` is the
  `policyRepoStatus` result; otherwise it is `null`. An unreadable or invalid state gives `null`,
  never a throw. `findCompany` keeps its current fields unchanged.

## `settings add-dir`
`assertSettingAllowed` also accepts the clone root (`samePath` with `company.policyRepo.path`)
when the status is `ok` or `moved`. In every other case, the refusal names both allowed folders.
`remove-dir` accepts the same values, so a stale permission can always be removed.
