# T64 — A coverage number we can trust, a gate, and the test rules

**Branch:** `test/coverage-gate` · **Size:** M · **Rules:** [README](README.md)
**Starts after T60 (#73) is merged** (this brief edits the T64 line next to T60's).

## Goal
Know how much of `scripts/lib` the unit suite really runs, stop it going down, and write
down the testing rules the last few PRs followed, so the next worker follows them too.

## Facts (measured 2026-11-23 on Windows, Node 22.23)
- The built-in coverage over the whole suite reports **66.7% lines** for `scripts/lib`:
  `node --test --experimental-test-coverage --test-coverage-include="scripts/lib/**" "tests/unit/**/*.test.mjs"`.
  **That figure is wrong.** It lists `secrets.mjs` at 74% lines and 20% functions, and
  `backup.mjs` at 32% lines, but the same command on one test file gives `secrets.mjs` 100%
  and `backup.mjs` 94%. `--experimental-test-isolation=none` gives the same wrong figures.
  Many files show "100% branches, 0% functions", which suggests a file is counted under two
  paths (for example `d:\` and `D:\`, or a `file://` URL against a plain path) and one copy
  is never run. Find the real cause; do not assume this one.
- Many tests run the CLI as a child process (`spawnSync(process.execPath, [cli, …])`).
  The built-in coverage does not see code run in those children. `NODE_V8_COVERAGE=<dir>`
  does: every Node process writes its V8 coverage there.
- The repository has **no npm dependencies** and CI runs `node --test` with no install. Keep
  it that way unless there is no other way; if a dev dependency is unavoidable, say why in
  the PR and stop at `DONE_WITH_CONCERNS`.
- CI (`.github/workflows/ci.yml`) runs on Windows, Ubuntu and macOS.

## Steps
1. **Find the cause** of the wrong whole-suite figure. Write it in the PR in two or three
   sentences, with the command that shows it.
2. **`tests/tools/coverage.mjs`**: runs the unit suite with `NODE_V8_COVERAGE` set to a temp
   folder (so child processes count), merges the per-process results for files under
   `scripts/lib/`, and prints one line per file (lines covered / total, percent) sorted lowest
   first, then a total. Use only Node built-ins (`node:v8`/`node:inspector` data as written to
   the folder, `node:fs`, `node:url`). A line counts as covered if any process ran it.
   Normalise paths (drive-letter case, `file://` URLs, separators) before merging.
3. `--min <n>`: exit 1 when the total is below `n`, printing the shortfall; exit 0 otherwise.
   `npm run coverage` runs it with the gate.
4. **Check the tool against the single-file runs.** For `secrets.mjs`, `backup.mjs` and
   `claims.mjs`, the merged figure must be at least the figure from running only that
   module's own test file. Put the three pairs in the PR.
5. **Set the gate** at the measured total rounded **down** to a whole number (not 85%, unless
   the real figure is above it). Record the figure in `docs/TASKS.md` on the T64 line. The
   ledger's 85% becomes the target, not the gate.
6. **CI:** one step on `ubuntu-latest` only (`if: runner.os == 'Linux'`) running
   `npm run coverage`, after the unit tests.
7. **`AGENTS.md`, `## Tests`** (at most 12 lines), the rules the recent PRs followed:
   - Test behaviour at a module's boundary: call the library, not a child process. One
     CLI test per command keeps argument parsing and exit codes covered.
   - One test per rule; variants of one rule are a table (`for (const c of CASES) test(…)`).
   - Never pin prose. Skill wording is tested only as a safeguard row in
     `tests/unit/skill-safeguards.test.mjs`.
   - Show a new test fails without the change (break the code, run, restore).
   - Coverage of `scripts/lib` never goes down: `npm run coverage`.
   - Fixtures come from `tests/helpers/workspace.mjs`.

## Done when
- `npm test`, `node scripts/validate-plugin.mjs` and `npm run coverage` pass locally.
- The PR states: the cause from step 1, the total and the ten lowest files, the three
  single-file comparisons from step 4, and the suite time with and without coverage.
- Lowering the gate by hand is the only way to make a coverage drop pass. Show it: delete
  one test file locally, run `npm run coverage`, paste the failing output, restore.
- T64 ticked in `docs/TASKS.md` with the PR link. The mutation spot-check is T64b, not this brief.
