# T76 — Restore makes `.devocd/` match the backup exactly

**Branch:** `fix/exact-restore` · **Size:** S · **Rules:** [README](README.md)

## Goal
After a restore, `.devocd/` is exactly the backup (except the parts that must survive), and the
restore itself can be undone.

## Facts
- `scripts/lib/backup.mjs`: `backupDir` copies `.devocd/` plus `CLAUDE.local.md` (and `CLAUDE.md`
  for a company) into `.devocd/.backups/<stamp>/`, keeping the newest 5.
- `restoreDir(dir, stamp)` copies each backed-up file back. Durable files (`.devocd/decisions.md`,
  `.devocd/decision-history/**`) are restored only when missing, so a newer capture wins.
- **Bug:** files created after the backup are never removed. Listed in `docs/repo-memory.md` Traps.

## Owns
`scripts/lib/backup.mjs`, the `restore` command in `scripts/devocd.mjs`,
`tests/unit/backup.test.mjs`, the restore section of the plugin README.

## Steps
1. At the start of a restore, back up the current state first and return its stamp too. The
   5-backup limit must never prune the backup being restored.
2. Remove files under `.devocd/` that are not in the backup, **except** `.backups/`, `draft/`,
   `journal/`, `runs/`, `stale.d/`, and durable decisions and history (today's rule kept).
   Remove emptied folders. Files outside `.devocd/` are restored as today, never deleted.
3. Check every target before changing anything: a symlink, junction or unexpected entry type
   anywhere under `.devocd/` refuses the whole restore with nothing changed. Reuse
   `checkTarget`, `lstatOrNull` and `fsutil.walk`.
4. `restoreDir(dir, stamp, { dryRun: true })` returns `{ stamp, copy, remove, keep }` (POSIX
   paths) and writes nothing. CLI: `restore <dir> [stamp] [--dry-run]`; update the usage line.
5. Docs: plugin README restore section (removes newer files, dry run first, how to undo);
   delete the `restoreDir` line from Traps in `docs/repo-memory.md`.

## Tests (`tests/unit/backup.test.mjs`, using `tests/helpers/workspace.mjs`)
- A page created after the backup is gone after restore; `draft/`, `journal/`, `.backups/` survive.
- A newer `decisions.md` and new history entries are kept; a missing durable file is recovered.
- A symlink inside `.devocd/` refuses the restore; every file byte-identical.
- Dry run changes nothing and lists the right files.
- Restoring the pre-restore backup returns the exact earlier state.
- CLI `--dry-run` and a usage error.
- Show "removed after restore" fails on the old code.

## Done when
All of the above pass, the README rules are met, and the PR lists every interpretation.
