# T112b — `check` names policies nobody uses

**Branch:** work on this branch (`feat/policy-unused`); it already carries this brief.
**Size:** S · **Rules:** [README](README.md) · **Needs:** T110 (#99), T112 (#100), both on `main`.
**Design:** [2026-11-25-policy-repo-design.md](../superpowers/specs/2026-11-25-policy-repo-design.md),
section 5 (`policy/unused`) and "Left to the builder" (how hook matches are counted).

## Goal
`check` on the company folder lists each policy that no page cites and no hook pointer has given
for `policyUnusedDays` days (default 90), as a candidate for deletion. It never claims "unused"
without enough history to know.

## Facts
- T110 records the pointers the prompt hook gives in `.devocd/journal/hook-stats.json` as
  `pointers: { "<file>": "<ISO time last given>" }`, newest 500 kept, plus `since` (when the
  counters started). The file lives in **the folder the hook ran in**: a project's own `.devocd/`
  when the prompt came from inside a project, the company's otherwise. `<file>` is repo-relative
  in repo mode and relative to `.devocd/standards/` in local mode.
- `readHookStats(dir)` in `scripts/lib/hookstats.mjs` reads that file (read-only; throws
  `HOOK_STATS_MALFORMED` for a damaged or linked file).
- Company state lists `projects: [{ id, path }]`, `path` relative to the company folder.
- `pagesCitingTopic(projectRoot, topic)` in `scripts/lib/check.mjs` (T112) lists a project's module
  and flow pages whose `Standards:` line names a topic. `readPolicyIndex` gives each index entry's
  `file` and `topic` (null when the name is not a valid topic).
- The company branch of `checkTree` already reads the active index: the policy repo's when one is
  recorded (`policyRepoIssues`, T112), else `.devocd/standards/index.md`.

## Decided by the controller
1. **Both modes.** The rule runs over the active index's entries: the repo's in repo mode, local
   standards otherwise. The pointer keys use the same relative form, so one rule covers both.
2. **Used** = some registered project has a module or flow page citing the entry's topic, **or**
   the newest pointer time for the entry's file, across the company's and every registered
   project's hook-stats, is within `policyUnusedDays`. An entry with no topic can only be used
   through pointers.
3. **Not enough history → no rule.** If no hook-stats file exists anywhere, or the oldest `since`
   among them is less than `policyUnusedDays` ago, the rule reports nothing. A damaged hook-stats
   file is skipped (not an error for this rule).
4. **`policyUnusedDays`** is an optional company state field: an integer from 1 to 3650.
   `stateProblem` refuses anything else. Absent means 90.
5. Severity `information`, one issue per unused file, `file` = the index path and `line` = its
   entry's line. The message names the policy file, never its contents.

## Tests
- One table over a company with two registered projects and a policy repo fixture (and one row in
  local mode):
  - cited by a page in either project → no issue;
  - given by the hook within the window, recorded in a project's hook-stats only → no issue;
  - neither cited nor given within the window → one `policy/unused` issue at the entry's line;
  - pointer older than the window → issue;
  - history shorter than the window (`since` recent) → no issue;
  - no hook-stats anywhere → no issue;
  - `policyUnusedDays: 7` changes the window.
- `stateProblem` refuses `0`, `3651`, `1.5` and `"90"`; accepts an absent field and `30`.
- Set times by writing the fixture's `since` and pointer timestamps; never sleep or mock the clock
  globally.
- Show each new test fails without its code.
