# Known limitations

- The license and the icon wait for the marketing step, so the plugin is not yet listing-ready.
- Flows guide an agent but can't force it to follow them.
- Ignored files live in one checkout only, and `git clean -xdf` deletes them.
- Reading company standards from a project session is refused under non-interactive `claude -p` unless the folder is granted (`additionalDirectories`) or Read is allowed; interactively it prompts.
- That `install` uses connector tools (Confluence, Jira and others) read-only is unverified against a real connector until the owner's trial in Task 10. Live runs use `--strict-mcp-config`, so no connector is present; the skill text requires read-only use, a static test checks that text, and the live runs check that no write-type connector call appears.
- In a non-interactive `install` approved by its answers file, the agent sometimes drafts in its own thinking and writes straight away, showing the draft's findings only in its report. The skill requires the draft before any write; that order is only checked by the owner's interactive trial in Task 10, since in a non-interactive run nobody can read the draft before the write anyway. A run that isn't approved always shows the draft and writes nothing, and the live tests check that.
- Under non-interactive `claude -p`, an `install` answers-file source outside the working folder is denied unless it is granted (`--add-dir` or a Read allow rule), as Task 4 observed for reads of a parent folder; interactive runs ask instead.
- `add-project` started inside a repo can't read the company folder above it (its standards and state) without a grant, so the helper's `preflight` locates the company and every company change goes through helper commands. Under non-interactive `claude -p`, the agent's own look at the company's `.devocd/` from inside a repo was denied and recorded; the run finished without it, and the flow names company standards by topic. Its answers file and sources outside the repo need a grant (`--add-dir`), as for `install`.
- `add-project` keeps the text of the `CLAUDE.local.md` block in `.devocd/pointer.md`, because the helper's `write-block` takes the block from a file. Edit that file and rerun `write-block`, or rerun `add-project`; the block itself is overwritten on every run.
- `add-project` takes a project folder and an answers file in one argument string, which the agent splits by a rule in the skill. Either part may be wrapped in one pair of double quotes, which are removed and don't count as a refused `"`. Unquoted, the answers file is the last space-separated part if it ends in `.json`, and the project folder is everything before it, so `my api answers.json` works. An answers-file path with a space must be quoted, or its first word would join the project folder. The agent applies the rule; no script parses it. The live tests pass a project folder with a space both quoted and unquoted; an answers path with a space is not tested.
- In a non-interactive `add-project` approved by its answers file, the draft-before-write order is recorded, not asserted, as for `install`.
- The warning when `install` runs in the home folder is tested by a unit test of `preflight` and a static check of the skill text, not by a live run, because a live run would have to override the home and Claude config folders and could break the login or touch the owner's real config.
- The live checks in `tests/e2e` cost real money and run only with `DEVOCD_LIVE=1`; they were observed on Claude Code 2.1.319 on Windows only.
- The personal split of a big team `CLAUDE.md` is offered by `add-project` only when the file is over 200 lines. It moves the file's lines into `.devocd/team/` by having the agent copy them, so the copy is checked live only by a share of lines found word for word, not line by line. Which lines count as rules is the agent's judgement; the draft lists what stays, what moves and what didn't fit so the user can correct it. Undo by the helper's `remove-exclude` is tested live; undo through a rerun with `personalSplit: false` is written in the skill but has no live run of its own. `.devocd/team/` is left in place after an undo.
